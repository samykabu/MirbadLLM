# LAN checkpoint sharing and llama.cpp throughput

Implementation plan for `feature/lan-model-sharing`, based on `f3b39ec`. Full paths are relative to the repository root. In shorter source references, a project prefix such as `Agent/` means `src/MirbadLLM.Agent/`. This adds to [the multi-node design, §§4, 6.4, 8 and 10](design.md) and [the process-runtime addendum, §§A.1.9 and A.2](design-p3p4.md). The three changes can ship independently. A move must finish preparing every required folder before it stops the source.

| Decision | Recommended implementation | Acceptance evidence |
|---|---|---|
| Where to serve Hub files | A dedicated HTTPS listener on the master on the DGX, with one additional **read-only** bind of the DGX models root. It can map registered sources to legacy DGX folders. The 4 TB volume stays on the host. | A native agent reads a shard from that volume. A missing shard comes from the official Hub at the same commit. |
| How to move a folder | The master streams bounded ranges from the source agent to the target agent over their existing mTLS data connections. The source grants read access to the authenticated master for one move and destination. | A folder-only model moves with the Hub disconnected. The master uses bounded memory and writes no checkpoint bytes to its volume. |
| Mirror cost per range request | Do not hash a whole file or call upstream on every range request. Keep a bounded digest cache keyed by file identity (absolute confined path, size, last-write time, and file id/inode). Hash a file once per identity in the background; never hold a response while hashing (the mirror client waits only 30 s for headers). While no verdict exists, serve a size-matching local file immediately, because every receiver verifies each file against the official manifest; a negative verdict sends later requests for that identity to the Hub. Any identity change invalidates the verdict. Cache the per-(repo, sha, path) anonymous authorization result for at most 5 minutes. The receiver still verifies every file. | A 20 GB shard downloaded in 8 MiB ranges is hashed once on the mirror, with at most one upstream authorization check per file per 5 minutes. |
| What to change for mac-pro | Trace a real b12681 request across the process, agent and master. Fix the first boundary that loses the measurement. The build has the expected counter but flushes generation statistics at slot reset. | A completed generation produces a measured rate on the affected model's page. If the report concerns a live stream, verify the live display during that stream as well. |

## 1. Route 1 — fetch a Hub checkpoint on the LAN

### Endpoint selection

* Add optional `Agent:HuggingFace:Endpoint` to `src/MirbadLLM.Agent/AgentOptions.cs`, and `MirbadLLM:HuggingFace:Endpoint` to `src/MirbadLLM.Core/MirbadLLMOptions.cs`. Examples are `https://models.lan:8444/` and an explicit node override of `https://huggingface.co/`. Use an absolute HTTPS origin, normalize one trailing slash, reject credentials, query, fragment and path prefix at startup. Keep the existing loopback HTTP exception confined to tests. Default when both keys are absent is the official Hub.
* Add nullable `fleetHubEndpoint` to the internal `DownloadStartRequest` in `src/MirbadLLM.Agent.Contracts/Storage.cs`. Populate it from master configuration when constructing operations in `Orchestration/Multinode/RemoteStorage.cs` and `MoveService.cs` (including restore via the remote downloader). Gate it on a new `downloads.hf-endpoint` flag in `Agent.Contracts/Protocol.cs`. An old agent takes the existing Hub path and its status should identify that limitation. An old master can use a new agent's local override. Do not accept a caller-supplied URL on the public download API.
* Resolve once **per operation** on the agent: local override, else fenced master value, else official Hub. Pass the result through preflight, metadata, file fetch, resume and helper creation. Store the selected non-secret origin and pinned revision with the job. Avoid changing a singleton client's base address between jobs. Use `IHuggingFaceRepoInspector` for editor/catalog inspection with the master's default. For a download the agent's selected origin governs both its preflight and its file requests. In `Agent/AgentServiceCollectionExtensions.cs:481-510` and `Orchestration/ServiceCollectionExtensions.cs:144-151`, remove the three independent URL literals in favor of this policy and one fixed **official origin** client for authentication, verification and fallback.
* `Agent/Storage/AgentDownloadService.cs:387-431` calls the inspector before the downloader. `NodeRuntime/HuggingFaceDownloader.cs:45-59,96-140` has a second listing and launches a Python helper with its own environment. Today the app supplies **no** `HF_ENDPOINT` and supplies no endpoint argument to `snapshot_download`. The SDK can honor an endpoint in the **helper's** environment at import time. Setting a variable on the agent or master alone does not configure the helper. Set it in `CreateJobContainerRequest.Env` before Python starts and pass the immutable SHA to the helper. Confirm with the actual configured `VllmImage` on arm64. [Hub SDK endpoint selection](https://github.com/huggingface/huggingface_hub/blob/v0.36.0/src/huggingface_hub/constants.py#L55-L65)

Use the host of the configured master Hub endpoint as the advertised mirror SAN, validate it against the listener certificate. Existing agent port 9443 is internal on the DGX. The master container, mac-pro, developmentpc and Docker helper network must resolve and reach the same advertised name. Configure split DNS/network alias if needed. Scope the port to the fleet LAN.
2. Add `src/MirbadLLM.Web/HubMirror/HubMirrorEndpoints.cs` and listener wiring in `Web/Program.cs`, using `Web/Enrollment/EnrollListenerTls.cs` as the listener pattern. Isolate routes by **local listener/port** before routing. The mirror offers only GET/HEAD to public Hub model content. UI, agent control, enrollment and directory browsing have no routes there. Reject authorization headers on this listener. Use a fixed public upstream; never proxy an arbitrary URL, request host or forwarded credentials.
3. Implement exactly these model routes, supporting a single repo name or owner/name. Parse raw segments once and validate repo, revision and file path with `HuggingFaceHubClient` and `RepoPathRules`. Do not let encoded separators in a filename change the folder selected. A revision on the listing route may be an escaped branch name.

   | Request | Required reply |
   |---|---|

One valid range yields 206 with exact `Content-Range`, unsatisfiable ranges yield 416 with `bytes */length`, a failed `If-Range` gets full 200. Omit Xet/redirect hints on locally served content. |

4. Implement `HubMirrorCatalog` beside the endpoints. On a lookup consider completed HF `DownloadManifest` entries and matching `ModelDefinition.Sources` for checkpoints physically on the bootstrap DGX. A source mapping is a *candidate location*, never proof that a folder matches a commit. This covers pre-feature container downloads with no native manifest. Where an unregistered legacy folder is important, use a validated repo/commit/path mapping from its HF local-dir metadata as a hint or register its actual source. Never guess identity from a basename. Do not hash or index the entire disk at startup.
5. Authorize against current official metadata, including explicit public/ungated status and an anonymous resolve HEAD for that SHA/path on **every** mirror content request. Private/gated, ambiguous visibility, failures and removed files cannot be served from disk. Cache immutable file metadata by repo + SHA, never cache an authorization decision across requests. Require official size plus LFS SHA-256 or `sha1("blob " + decimalSize + NUL + bytes)` for Git blobs. Hash the safely opened candidate before serving the requested range and stream from that handle. A bounded digest cache may follow only for demonstrably immutable files. Missing/modified/unsafe candidates fall through to the **fixed official resolve URL** at the same SHA. Follow only legitimate HTTPS Hub/CDN redirects using ordinary public PKI and no credentials. Relay file metadata/range semantics consistently. Never serve size-only local hits.
6. The consumer also pins the authoritative listing. For a mirror job resolve the requested ref and patterns once against the **official Hub over its own normal TLS client**, compare the mirror listing at that commit, and persist the official selected manifest before accepting bytes. A small WAN metadata request is intentional. A mirror controlling both metadata and bytes cannot redefine the snapshot. Mirror listing mismatch, false ETag, same-size corruption or missing digest cannot promote a file. For an entry without a Hub digest, bypass the mirror and fetch fresh from the canonical origin with the direct path's size check. Keep per-file fallback pinned even if the original branch advances.
7. Reuse `NodeRuntime/Downloads/Native/{HuggingFaceHubClient,NativeSnapshotDownloader,RangeDownloader,ContentDigest,DownloadManifest,SecureDownloadTransport}.cs`. Split metadata authority from byte origin in `Agent/Storage/NativeDownloadService.cs`. Revalidate existing files against the expected digest on a LAN acquisition, including files previously marked verified. The current same-length fast path for a verified native entry cannot detect a subsequent local edit. Reject reserved paths, collisions, traversal and links on both ends as in §2. If bytes change during streaming, receiver verification prevents promotion.
8. For `downloads.hf-container`, retain the helper and its cancellation/monitoring lifecycle. For mirror jobs give it the agent-selected **exact files**, already validated, and call the existing SDK's `hf_hub_download` for each path with `revision=commitSha`, `endpoint=HF_ENDPOINT`, `local_dir` in staging and anonymous auth. This avoids a second SDK-selected file list or a moving branch and limits the protocol needed to HEAD/GET resolve. Disable Xet and implicit token lookup in this mode. Limit mirror requests to this origin and reject redirect/downgrade in the helper's HTTP adapter (test the installed SDK's requests/httpx generation). The built-in mirror proxies misses itself. Run a new helper with public TLS policy for a direct fallback. Keep the existing `snapshot_download` direct path for ordinary jobs. Before reporting success on a mirrored job, let the agent hash all selected bytes using the same official manifest, including local-dir cache hits, and write the completed native-compatible marker. The current exit-code/byte-count logic at `HuggingFaceDownloader.cs:202-273` is insufficient. Persist pre-finalization state so an agent restart cannot promote a merely exited helper. Limit selected files/manifest bytes as in `NativeDownloadOptions`. Use the target staging/conflict rules below.

### TLS and private content

* Reuse the master's rotating **serverAuth** enroll credential, with the dedicated mirror DNS/IP included in `MirbadLLM:Enrollment:ListenerAddresses`. `Pki/CertificateAuthority.cs:149-180` distinguishes the client-only master credential from the server leaf with address SANs. Select the current server leaf on each handshake through the same lifecycle as `Orchestration/Pki/MasterCertificates.cs`. Use the existing CA rotation overlap. No additional signing key on an agent.
* For a fleet-issued mirror on .NET construct a handler for the **exact configured origin** using `X509ChainPolicy.CustomRootTrust`, the current anchors from `RotatingAgentCredentials.TrustAnchors` (master uses its PKI trust store), validity, serverAuth, and normal DNS/IP SAN matching. Rebuild on anchor change. The agent mTLS handler verifies node identity differently and is unsuitable as a general Hub handler. Reject name, chain and expiry errors. The official Hub and redirected CDN connections always use the system's public roots. Leave any publicly issued custom endpoint on normal hostname + public PKI validation as a separate explicit trust choice at configuration, e.g. `HuggingFace:Trust = FleetCa | System` alongside each endpoint, default FleetCa for custom and System for official. Propagate the nullable `fleetHubTrust` with `fleetHubEndpoint`; a node override selects its own trust policy. If an existing enroll leaf lacks the new SAN, reissue it through the normal master credential lifecycle before advertising the listener.
* For Docker, export only the current **public** PEM anchors from the agent's enrolled `ca.crt` to a protected per-job file in `Agent:CacheRoot`. Bind the corresponding **daemon-side** path under `Agent:CacheHostPath` read-only at `/run/mirbad/hub-ca.pem` in the helper. Match the helper UID's read access. Set both `REQUESTS_CA_BUNDLE` and `SSL_CERT_FILE` for that fleet-mirror job. Do not mount the PKI state directory, keys or Docker socket in the helper. Direct public jobs use the image's normal public CA bundle and receive no fleet CA environment override. Recreate an interrupted helper with fresh anchors following rotation, retire revoked roots and remove temporary public bundles when the helper exits. Test from **inside** the deployed image. Trust in the agent container alone does not cross Docker's boundary.
* Token supplied or official authority reports gated/private: go directly to the official Hub over public TLS. An anonymous denial preserves the existing needs-token/access-denied flow. Treat a private repo hidden behind 404 as unknown or requiring access. Do not forward a token to the mirror, a custom endpoint or CDN. Reuse in-memory move tokens, payload redaction, secret-free status/operation records and helper cleanup. A restart that loses a required token must request it again. Route 2 is a fleet operator copying an already held local checkpoint, including restricted models, under a move grant. That permission does not make the bytes available on the mirror.

## 2. Route 2 — move a checkpoint over mTLS

### Authority, files and wire contract

Use the existing master→agent TLS connections in both directions of data flow. The source serves the master, the master pushes to the approved target. This works when DGX port 9443 is reachable only by the master container. It requires no agent peer allowlist, new firewall ingress or client key export. A transfer between mac-pro and developmentpc costs two LAN legs through the DGX. Bound the relay and preserve inference capacity.

* Add feature `storage.move-transfer-v1` in `src/MirbadLLM.Agent.Contracts/Protocol.cs`. Define the following proposed contracts in `Agent.Contracts/Storage.cs`, register them in `AgentRoutes.All`, `IAgentClient.cs`, `Operations.cs` and the agent route/feature contributor. Implement control in `Agent/Api/StorageEndpoints.cs`, `Agent/Storage/MoveTransferService.cs` (new) and `Orchestration/Agents/AgentClient.cs`. Binary GET/PUT use the pinned, rotating data handler in `AgentDataClient.cs`; add transfer-specific methods/URI builders with bounded streaming, outside the inference proxy. Use the actual negotiated protocol header, mutation envelope, master triple, request time, idempotent operation log and structured agent errors. No generic remote-file endpoint.
* The table uses paths relative to `/agent/v1`. Use `MirbadLLM-Transfer-Grant` for the lease header. Mark `grant` as secret in `Protocol.SecretFieldNames` and exclude it from response/request logging, including headers. JSON uses web defaults. `Grant` below means an agent-side, unpredictable 256-bit lease handle carried in a **redacted header**, never in URLs. Only the pinned/current master mTLS identity with the matching fenced triple can use it. A node leaf, anonymous client or older master cannot read it. No stateless token or JWT library needed.

| Call | Wire and semantics |
|---|---|
| `POST /move-transfers` on source or target | `MoveTransferOpenRequest : AgentMutation` includes `moveId, role: export\|import, sourceUid, targetUid, modelId, placementGeneration, folder, manifestId?`. Import also receives the validated manifest. Validate local UID/role, master fence and single folder scope. Reply 202 with operation id and transfer id. Building/hashing the export runs as a cancellable operation. |
| `GET /move-transfers/{id}` | Authenticated status `{transferId, operationId, role, phase, bytesDownloaded, totalBytes, fileIndex?, nextOffset?, error?}`. When ready, source makes the immutable manifest available via `GET /move-transfers/{id}/manifest` with grant. Target reports verified files and the next durable offset. Completed target with identical contents can immediately report `completed`. |
| `POST /move-transfers/{id}/lease` | Fenced mutation, bound to the same move, UIDs, generation, folder, role, manifest and current master boot. Returns `{grant, expiresAt}` only on the mTLS response. Grant is held in memory at both ends, only its hash at the agent. Issue on open/poll and renew at half of a five-minute TTL. Lost response/replayed lease operation must not expose a secret through operation history; request a fresh lease with a new envelope. |
| `GET /move-transfers/{id}/files/{index}` (source) | Grant plus single bounded `Range: bytes=start-end`, `If-Match: "sha256-…"`. Only indexes in the approved manifest. Reply 206, exact `Content-Range`, length and strong ETag. 412 on generation/content precondition change, 416 for bad bounds. No filesystem path in the URL. |
| `PUT /move-transfers/{id}/files/{index}` (target) | Grant, `If-Match` manifest id, `Content-Range: bytes start-end/size`, exact `Content-Length`, binary body. Stream only at the target's reported offset under the active import lease. Persist offset **after** a successful write/flush; return acknowledged offset. Duplicate/lost reply returns current offset, mismatched offset gets 409 and target status. Interrupted writes truncate to last durable offset before retry. Create zero-length files at import with hash verification. |
| `POST /move-transfers/{id}/finish` or `/cancel` | Fenced idempotent mutation. Finish on target verifies all files then publishes, on source closes export. Cancel revokes grants, stops streams and releases reservations. A terminal operation has a secret-free result. Polling status and cancellation work after a master reconnect. |

The raw PUT belongs to the admitted import operation. Give each chunk the fenced master headers, opaque lease and expected offset; do not deserialize its body as a JSON mutation or create a second operation-log entry per chunk. Register the GET/PUT as raw data-channel routes. Dispatch control mutations through `Agent/Storage/StorageOperations.cs` and reconcile/cancel imports and exports in `Agent/Storage/StorageRecovery.cs`. Apply distinct structured outcomes: 403 for invalid/expired grant, 409 for offset/folder conflict, 412 for changed manifest, and the existing insufficient-disk/fencing codes where applicable.

Each data call checks live lease, TLS identity, audience, transfer id, role, expiry and fencing state, including renewal while hashing. The master checks ownership is still at `downloading`, current placement/generation, both approved UIDs, revocation and target admission before issuing/renewing and before each range. On fence change, revocation, expiry or cancel, abort active streams and refuse new ones. On lost master, leases expire locally. After restart, revalidate the persisted ownership and manifest and issue a new lease under the new boot. An agent's existing control listener continues to accept master identity only. On the target a grant can write only to its own private staging area.

**Manifest.** Use a distinct `MoveFolderManifest {version:1, files:[{path,size,sha256}], manifestId}`. Sort portable relative paths by ordinal comparison; compute `manifestId` as lowercase SHA-256 over `OperationPayload.Canonicalize` of `{version,files}`. Cap at the native maximum files and manifest bytes, check sums for overflow. Every regular file in a folder-only checkpoint gets a SHA-256, including config, tokenizer, split shards and auxiliary model files. Exclude only known download/cache bookkeeping (`.cache/huggingface`, Mirbad manifest/legacy marker, recognized staging files) and VCS metadata. Hidden model assets remain eligible. Reject special files and links rather than silently producing an incomplete model. A native HF manifest identifies files and Hub provenance but may contain Git blob ids, size-only entries or only a subset. A move manifest describes the actual payload. Never fabricate a Hub repo or commit for a locally imported model.

**Confinement and consistency.** Start at the agent's configured `models` logical volume via `ModelRootPaths.Locate`. Reject linked folder roots, partial/in-progress downloads, escaping paths and files outside the granted folder. Validate manifests at both boundaries using `RepoPathRules.CheckAll`, including device names, ADS, duplicates, file/directory conflicts and case/Unicode-normalization collisions on destination filesystems. Enumerate only regular files, refuse devices/FIFOs and unsafe hard links. Recheck the opened file/directory handles under the original root to close validation/open races. Reuse `WindowsFinalPath` and reparse checks on Windows; on Unix anchor traversal to a directory handle and use no-follow relative opens for every component. Use the same confined reader on the mirror. Hash opened files under a folder reservation shared with download/delete/import. Capture file identity, size and modification generation; recheck when serving and at finish, detect additions/removals, and fail a changing source snapshot. Target recomputes SHA-256 over full files, including resumed prefixes. An inconsistent snapshot cannot progress to source stop.

**Disk and flow control.** Check staged bytes remaining plus `AgentStorageOptions.DiskHeadroomFraction` with `IDiskSpaceProbe`. Reserve the folder in the same exclusion path used by `AgentDownloadService` and `ModelFolderService`; reject conflicting writers and target folders in use. A missing target stages on the same volume under an agent-owned partial directory keyed by move + manifest id, hidden from listing, launch and native HF recovery. Persist a secret-free transfer journal outside payload paths. Rename atomically after verification. For an existing target, hash for equality first. Bring forward matching files and fill genuinely missing files with individually verified temporary files and atomic no-overwrite renames under the folder reservation. Keep it unavailable as a completed candidate until the journal commits. On differing files, incompatible extra payload or conflicting writer, refuse with `folder_conflict` and preserve existing data; never replace a differently populated folder shared by another model. Existing HF selections may retain unrelated files under the established Complete policy when the selected files and all launch dependencies verify. Account for staging space, acknowledge only verified success, reconcile a crash between rename and journal commit by rehashing.

Use one active stream per involved node, one file at a time, 8 MiB maximum single range, and a 256 KiB pooled relay buffer. Bound and throttle the stream under backpressure; no whole-file byte array, unbounded HTTP buffering, master temp file or base64-in-JSON. Recommended default `MirbadLLM:Moves:MaxTransferMiBPerSecond = 64` aggregate per participating node (positive integer, both legs charged on remote-to-remote moves). Await cancellable pacing via `TimeProvider`, respect server busy/retry-after and native read-idle timeout. Between chunks re-check ownership; cancel an outstanding HTTP call immediately on move cancellation. Verify lengths/ranges before forwarding, discard failed range bytes on target and query offset after ambiguous errors. Log bytes, route, node ids and error code only.

## 3. mac-pro — find the first missing measurement

**Confirmed on the live fleet (2026-11-25).** Master `/api/status`: `inkling-2-mini-mac` (llama.cpp process on mac-pro) and `bonsai-25-27b-ternary` (llama.cpp) both report `runningRequests: 1` with `generationTokensPerSecond: 0`, while the vLLM model on the DGX reports 62.9 under load. This is the completion-only counter described below. Implement the live-rate measurement in step 4 (`/slots` active decoded tokens, composite `completed + active`) as the fix, for every llama.cpp delivery (process and container). Steps 1-3 are not needed.

**What the code establishes at this revision.** There is a real reason for a zero rate *during* a long b12681 generation. The stock server adds the slot's generated tokens to the cumulative counter on slot reset. Its metrics request returns the accumulated stats. MirbadLLM differences that counter per sampling interval. One busy slot can therefore produce zero during streaming and a spike after completion. This does not explain a persistent dash or the absence of a post-completion delta. Neither the runtime binary actually launched nor the live scrapes of `inkling-2-mini-mac` are present in this worktree. [b12681 reset callback](https://github.com/ggml-org/llama.cpp/blob/b12681/tools/server/server-context.cpp#L1441-L1451), [metrics snapshot](https://github.com/ggml-org/llama.cpp/blob/b12681/tools/server/server-context.cpp#L2867-L2884), [counter accumulation](https://github.com/ggml-org/llama.cpp/blob/b12681/tools/server/server-context.cpp#L4655-L4665), [Prometheus names and prefix](https://github.com/ggml-org/llama.cpp/blob/b12681/tools/server/server-task.cpp#L1478-L1555).

### Scope decisions

This release provides a read-through source for public HF model files and move-scoped export of an operator's local folder. It leaves out a general Hub proxy, private-model redistribution, offline branch resolution, background replication, peer discovery, a settings UI, new runtime conversion, Ollama distribution and automatic source deletion. The DGX models-root bind is an explicit deployment assumption. Source copy/destination verification also work when the master has no mirror mount. The live mac-pro cause remains conditional until the measurements in §3 identify the affected boundary.
